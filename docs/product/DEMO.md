# 演示与验收

## 启动

需要 Go 1.22+，从 PerfMan 根目录：

```sh
cd studio
go run ./cmd/perfman
```

打开 http://127.0.0.1:8099 。依赖 Go 标准库，无前端构建步骤。编辑静态资源后重启 Go，重新嵌入资源。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| PERFMAN_ADDR | 127.0.0.1:8099 | 默认仅本机监听 |
| PERFMAN_DATA | data/state.json | 相对 studio 工作目录；可指定绝对路径 |

配置仓库不参与 Studio 启动。本地目标是程序内置的 /demo-api/，不是云端真实业务。没有登录或生产多租户能力，使用合成凭据。

## 5 分钟演示脚本

1. 进入测试场景，打开商城下单链路。展示登录提取 token，商品与订单传递请求头。
2. 保存并调试，观察 3 个请求、一个完整事务、状态码断言通过。
3. 返回场景，运行商城下单链路。等待约 20 秒，查看阶梯 VU 对应的吞吐变化、逐接口时延和最终通过判定。
4. 运行订单服务瓶颈复现。订单接口有受控慢响应和周期性 503，约 4–6 秒可看到连续窗口 SLA 停止。
5. 打开报告对比，选择正常和瓶颈两次运行。强调环境/配置不同，差异可以定位瓶颈，但不直接认定版本回归。重复同一场景两次则可演示条件一致的比较。
6. 下载 JSON 和 CSV；查看报告中的 source、冻结的场景和执行状态。打印比较页可保存 PDF。
7. 复制场景、改名、调整阈值、保存。查看旧报告，名称/版本/阈值应仍保持原快照。
8. 新建任务后点击停止，结果为 stopped/incomplete；正常结束但阈值未达标的结果为 completed/failed。
9. 重启后已有结果仍在。异常结束的在途任务不会自动当作成功或续跑。

## 实际验证

自动测试：

```sh
go test -race ./...
node --test tests/domain.test.mjs
```

Node.js 22 用于前端领域测试；运行应用无需 Node。验收结果见 [VALIDATION.md](VALIDATION.md)。

重要测试覆盖：真实业务链路、变量提取、冻结快照、旧版本拒绝、同时运行准入、取消退出、真实窗口 SLA、重启中断、状态损坏拒绝覆盖、保存失败不启动，以及非法目标与跨源写入。

## 导出 k6

本地编辑已保存场景时选择“导出 k6 脚本”。需要自行安装 k6，导出后可执行：

```sh
k6 run perfman-checkout.js
```

默认 BASE_URL 是本地演示服务。只把 BASE_URL 改为自己有权限测试且实现相同路径的目标。导出与内置执行器在 ramp 形状、最终判定/窗口自动停止上存在差异，文件中有注释。本次没有运行 k6，也没有宣称 Studio 已托管 k6 进程。

## 在线展示

在线入口是单独打包的静态交互展示，采用当前浏览器 localStorage 保存。它不向目标发送请求，全部曲线与报告带 synthetic 来源；预置样例和随后运行均是合成数据。与本地版的数据互不相通。不要用其数值评价实际系统容量。

## 重置与数据

停止本地进程后，先导出或备份 state.json，再将它移到其他位置。重新启动会创建新的种子项目和场景。不要在运行时删除数据文件。在线展示可通过浏览器清理该站点的数据重置。
